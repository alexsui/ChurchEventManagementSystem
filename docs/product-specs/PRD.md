## 2. 專案概述

### 2.1 專案背景

本專案旨在為教會開發一套活動管理系統，取代目前以 Google 表單 + Excel + LINE 群組為主的工作流程。系統需支援約 200 名會員，涵蓋從活動企劃、報名、出席追蹤到預算管理的完整流程。

### 2.2 現況痛點

教會目前的行政作業模式存在以下痛點：

- 報名／出席紀錄分散在多個 Google 表單與 Excel 檔案中，容易出錯
- 各組別（行政／總務／影音／敬拜／破冰／牧養）溝通依賴 LINE 群組，資訊難以彙總
- 活動分次舉行時，每次人數與名單追蹤費時費力
- 總務組需要手動統計預算（午餐、茶點、場佈等）
- 傳道人無法即時了解參加者背景與各組準備狀況
- 課程作業繳交與完成狀況無系統化追蹤方式

### 2.3 系統規模

| 項目       | 說明                                                                 |
| :--------- | :------------------------------------------------------------------- |
| 會員人數   | 約 200 人                                                            |
| 活動頻率   | 約每月一次                                                           |
| 使用者角色 | 行政同工、總務同工、財務同工、傳道人、多媒體同工、各組組長、一般會員 |
| 現有工具   | Google 表單 + Excel + LINE 群組 + 紙本 + Word                        |
| 痛點頻率   | 每月（有活動時較明顯）                                               |

## 3. 系統範圍

### 3.1 納入範圍 (In Scope)

系統涵蓋以下八大功能模組：

1. **活動管理** — 活動建立、編輯、狀態管理，支援單場與系列活動
2. **報名管理** — 線上報名表單、QR Code、名額管理
3. **出席管理** — 報到、出席追蹤、遲到標記、結業條件判定
4. **作業管理** — 課程作業指派、上傳繳交、完成度追蹤
5. **工作人員與分組** — 服事組別管理、任務指派、SOP 文件共享
6. **會員資料與分類** — 會員基本資料、屬性標籤、自動分組、參加歷史
7. **預算與總務** — 預算編列、實際支出、對比報表
8. **統計與報表** — 報名／出席統計、趨勢分析、參與度報表

### 3.2 排除範圍 (Out of Scope)

以下功能明確不在本系統開發範圍內：

- **金流系統** — 不處理任何付款、收費、奉獻或財務交易功能
- **美編／文宣設計功能** — 不提供海報、文宣、圖片設計或編輯工具

## 4. 使用者角色與權限

### 4.1 角色定義

| 角色       | 可查看／操作                                         | 使用頻率       |
| :--------- | :--------------------------------------------------- | :------------- |
| 統籌者     | 全系統管理、帳號權限控管、權限期限設定               | 高（持續）     |
| 行政同工   | 跟進報名名單狀況、製作報到單、表單管理               | 高（每週）     |
| 總務同工   | 查看報名人數、預備午餐／茶點／場佈／設備等實務       | 中（活動前）   |
| 財務同工   | 預算編列、實際支出紀錄、預算對比報表                 | 中（活動前後） |
| 傳道人     | 了解參加者背景、查看各組準備狀況、牧養追蹤           | 中（活動前後） |
| 多媒體同工 | 查看活動資訊、管理所屬組別（多媒體組）任務與資料     | 中（活動前）   |
| 影音組長   | 查看／編輯影音組相關任務與資料                       | 中（活動前）   |
| 敬拜組長   | 查看／編輯敬拜組相關任務與資料                       | 中（活動前）   |
| 其他組長   | 查看／編輯所屬組別相關任務與資料（破冰組、牧養組等） | 中（活動前）   |
| 一般會員   | 登入後報名活動、查看自己的活動與出席資訊             | 低（活動時）   |

### 4.2 權限管理機制

- 組長帳號採**時間限定權限**機制：活動期間開啟存取權限，結束後由統籌者關閉
- 統籌者可控管各帳號的權限範圍與有效期限
- 所有使用者皆需註冊帳號並登入
- 提供兩種登入方式供所有人自由選擇：**LINE Login** 或**帳號密碼**
- 登入方式與角色無關，角色由統籌者在後台指派
- 新人首次使用需先註冊（可透過 LINE 一鍵註冊），舊用戶直接登入

### 4.3 傳道人牧養追蹤需求

傳道人角色需能查看以下會員資訊：

- 過去參加紀錄（歷次活動與課程）
- 介紹人（誰介紹該會員前來）
- 參加過的小組紀錄
- 特殊備註

## 5. 活動生命週期

根據客戶確認，一個活動從企劃到執行的完整流程如下：

| 階段 | 主要事項                         | 系統對應功能                                 |
| :--- | :------------------------------- | :------------------------------------------- |
| A    | 開會企劃：決定日期／時間／內容   | 活動建立與資訊編輯                           |
| B    | 製作報名表單／QR Code            | 報名表單產生器 + 分享連結                    |
| C–D  | 尋找服事同工／分工／建 LINE 群組 | 工作人員指派與分組管理                       |
| E    | 每週跟進報名狀況                 | 即時報名儀表板 + 每次人數／名單查看          |
| F–G  | 各組開會／擬定 SOP               | 各組任務清單與進度追蹤                       |
| H–I  | 各組準備／分組歸納名單           | 會員屬性分類（年紀／性別／家庭狀況）自動分組 |
| J    | 數據統計                         | 報表與統計儀表板                             |

## 6. 功能需求

### 6.1 活動管理

- 建立／編輯／刪除活動（包含日期、時間、地點、活動說明）
- 支援**單場活動**與**系列活動**兩種型態：
  - 系列活動範例：幸福小組（5–6 次）、恩惠相遇（4 次）、啟發外展（5–6 次）、興趣外展活動（5–8 次）、成長班（10 堂）、音樂研習課（4 課）
- 支援**單場報名**與**整期報名**兩種報名模式
- 各次活動獨立追蹤人數與名單
- 追蹤參加者背景資訊（居住區域／城市、年齡、如何得知活動、介紹人）
- 活動狀態管理（企劃中／報名中／進行中／已結束）

### 6.2 報名管理

- 線上報名表單（可產生 QR Code 分享）
- 報名狀態追蹤（已報名／已取消）
- 名額管理（人數上限、候補機制）

### 6.3 出席管理

- 活動當天報到功能（QR Code 掃描或手動點名）
- 系列活動每次出席紀錄
- 缺席追蹤與通知
- **遲到標記**：支援標記「是否遲到」，部分課程（如培育系統）規定遲到 20 分鐘以上視為缺課
- **結業條件判定**：
  - 出席率百分比要求（依課程設定門檻）
  - 搭配作業完成比例作為結業依據

### 6.4 作業管理

- 依課程每堂課指派作業項目
- 支援檔案上傳繳交作業
- 作業完成狀態追蹤（已繳交／未繳交）
- 功課完成比例統計（作為結業判定條件之一）

### 6.5 工作人員與分組

- 服事組別管理（行政組／總務組／影音組／信息組／敬拜組／破冰組／牧養組）
- 任務指派與進度追蹤
- 各組 SOP 文件儲存與共享

### 6.6 會員資料與分類

- 會員基本資料（姓名、聯絡方式、年齡、性別、居住地區、得知活動來源）
- 屬性標籤（家庭／單身／年長／青年／學生等）
- 自動分組功能（依屬性分配小組或內容）
- 參加歷史紀錄
- **兒童營會特殊欄位**：
  - 孩童注意事項
  - 用藥提醒（是否需要幫忙提醒吃藥）
  - 飲食限制（有什麼不能吃的）
  - 接送人資訊（姓名與聯繫電話）

### 6.7 預算與總務

- 活動預算編列（午晚餐／茶點／場佈／材料／設備等）
- 實際支出紀錄
- 預算 vs. 實際對比報表

### 6.8 統計與報表

- 報名／出席統計儀表板
- 每次活動人數趨勢
- 會員參與度分析

## 11. 已確認事項（原待確認）

以下問題已與利害關係人確認，結論如下：

### 11.1 會員制度定位（已確認）

**Q11 結論：所有參加活動的人都必須先註冊為會員。**

- 系統中只有一種身份：「使用者（User）」，透過角色（role）區分管理者與一般會員
- 新人需先註冊帳號，舊用戶直接登入
- 不再有「匿名公開表單報名」的流程

**Q12 結論：外部人士（慕道友等）也需要註冊帳號才能報名。**

- 統一視為使用者，用標籤區分身份（如「慕道友」、「社區朋友」）
- 註冊門檻透過 LINE Login 降到最低

**Q13 結論：不再需要比對機制。**

- 每個使用者有唯一帳號（LINE ID 或帳密），報名時直接關聯，不存在重複比對問題
